# Hangar Phase P6 — Skills + curated agent templates

**Weeks:** 13-14
**Builds on:** P0 (schema: `skill`, `skill_file`, `agent_skill` tables), P1 (per-task workdir + dispatch path), P4 (Skill manager screen scaffold)
**Blocks:** P7 (autopilots reference skills), P8 (observability surfaces skill activations)
**Sub-beads:** 5 (`hangar:P6.1` through `hangar:P6.5`)

## Goal

Wire two skill sources into Hangar:
1. **Embedded curated `agent_template` JSONs** baked into `ainb-hangar-daemon` binary at compile time (Multica pattern — repo-only, PR-reviewed, never DB-mutable).
2. **Importer from `toolkit/packages/skills/`** via `ainb hangar skills sync` CLI — workspace-scoped, idempotent.

At dispatch time, daemon materialises every `agent_skill` row into the per-task env at the provider-native path (claude → `.claude/skills/`, codex → `~/.codex/skills/`, gemini → `.agent_context/skills/`). Skill manager screen (P4 stub) becomes fully functional.

## Out of scope

- Skill marketplace, version pinning, hash lockfile (defer)
- Importing from URLs (skills.sh, GitHub) — defer to P9+
- Sandboxing skill scripts — security review at P5 accepted "trust-the-user-with-warnings"
- Local skill discovery from `~/.claude/skills/` — defer; ainb users curate via toolkit

## Architecture sketch

```
toolkit/packages/skills/<name>/SKILL.md      embedded agent_template JSONs
        │                                            │
        ▼                                            ▼
ainb hangar skills sync                  include_str! in ainb-hangar-daemon
        │                                            │
        ▼                                            ▼
  skill + skill_file rows         agent_template registry (in-memory)
  (workspace-scoped)                          │
        │                                     ▼
        ▼                          ainb hangar templates use <name>
   agent_skill row (M:N)              creates agent + imports skills
        │
        ▼
  dispatch (P1 path)
        │
        ▼
  materialise into ~/.ainb/hangar/workspaces/{ws}/{tid}/skills/
  + symlink/copy into workdir at provider-native path
```

```rust
pub struct SkillRepo<'a> { pool: &'a SqlitePool }

impl<'a> SkillRepo<'a> {
    pub async fn create(&self, ws: WorkspaceId, name: &str, desc: &str,
                        content: &str, files: Vec<SkillFileInput>) -> Result<SkillId>;
    pub async fn list(&self, ws: WorkspaceId) -> Result<Vec<SkillRow>>;
    pub async fn get(&self, id: SkillId) -> Result<Option<SkillRow>>;
    pub async fn upsert_by_name(&self, ws: WorkspaceId, ...) -> Result<SkillId>;
    pub async fn attach_to_agent(&self, agent: AgentId, skill: SkillId) -> Result<()>;
    pub async fn detach_from_agent(&self, agent: AgentId, skill: SkillId) -> Result<()>;
    pub async fn files_for(&self, id: SkillId) -> Result<Vec<SkillFileRow>>;
    pub async fn skills_for_agent(&self, agent: AgentId) -> Result<Vec<SkillWithFiles>>;
    pub async fn delete(&self, id: SkillId) -> Result<()>;
}
```

```rust
pub async fn skills_sync_from(repo: &SkillRepo<'_>, ws: WorkspaceId,
                              root: &Path) -> Result<SyncReport, SyncError> {
    let mut report = SyncReport::default();
    for entry in walk_skill_dirs(root)? {
        let skill = parse_skill_md(&entry.skill_md)?;
        let files = collect_assets(&entry.dir)?;
        let id = repo.upsert_by_name(ws, &skill.name, &skill.description,
                                     &skill.content, files).await?;
        report.imported.push((skill.name, id));
    }
    Ok(report)
}
```

### GREEN

```rust
pub struct Materialiser<'a> {
    repo: &'a SkillRepo<'a>,
    task_root: PathBuf,             // ~/.ainb/hangar/workspaces/{ws}/{tid}/
    workdir: PathBuf,               // task_root/workdir
    provider: Provider,
}

impl<'a> Materialiser<'a> {
    pub async fn materialise_for_agent(&self, agent: AgentId) -> Result<MaterialiseReport>;
    fn skill_root_for(&self, provider: Provider) -> PathBuf {
        match provider {
            Provider::Claude   => self.task_root.join(".claude/skills"),
            Provider::Codex    => self.task_root.join(".codex/skills"),
            Provider::Copilot  => self.workdir.join(".github/skills"),
            Provider::Cursor   => self.task_root.join(".cursor/skills"),
            Provider::Gemini |
            Provider::Default  => self.workdir.join(".agent_context/skills"),
        }
    }
}
```

Env vars set in P1's `Command::env(...)` for agent subprocess:
- Claude: `CLAUDE_HOME=$task_root` (CLI finds `.claude/skills/`)
- Codex: `CODEX_HOME=$task_root/.codex`
- Cursor: `CURSOR_HOME=$task_root/.cursor`
- Gemini: no env var; skills land inside workdir at `.agent_context/skills/`

Wire `Materialiser::materialise_for_agent` into P1 dispatch path after `git worktree add` succeeds and before `Command::spawn`.

### REFACTOR

- `ProviderSkillLayout` enum so adding new provider = one match arm + one test
- Copy on macOS/Linux (Multica copies; symlinks would break some sandbox checks)
- `MaterialiseReport { files_written, total_bytes, skill_names }` for P8 observability

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Provider-native skill paths drift between agent CLI releases | Med | Pin tested CLI versions in CI; document expected layout per provider |
