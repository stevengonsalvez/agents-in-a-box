# P7 — Autopilots + cron scheduler (Weeks 15-16)

**Phase:** P7
**Sub-beads:** 6
**Builds on:** P0 (schema), P1 (TaskService + FSM), P4 (TUI screens)
**Blocks:** P8 (observability surfaces autopilot run metrics)
**Out of scope:** webhook autopilots, api-trigger autopilots, cloud-runtime targeting

## Goal

Cron-scheduled autopilots. Daemon thread reads `autopilot` rows, fires at next tick, enqueues `agent_task_queue` row with `autopilot_run_id` set. CLI + TUI surfaces. Skip ticks when prior run still in flight. Webhook + api triggers explicitly deferred (Multica `autopilot_trigger` table reduced to single `cron_expr` column on `autopilot` row — no separate trigger table at v1).

## Decisions locked

- Crate choice: `cron` v0.12 (parser only; no built-in scheduler). Tokio task drives tick loop. **Reject** `tokio-cron-scheduler` — pulls `uuid` + `chrono` macros + own runtime; harder to inject clock for tests.
- Clock injection: reuse `HangarClock` trait from P0. Tests use `FixedClock`; prod uses `SystemClock`.
- Concurrency policy: `max_concurrent_runs INTEGER NOT NULL DEFAULT 1` on `autopilot` table. Tick skipped if `SELECT count(*) FROM autopilot_run WHERE autopilot_id = ? AND completed_at IS NULL >= max_concurrent_runs`. Multica's `skip|queue|replace` enum collapsed to single integer for v1.
- Skip event audit: skipped ticks logged via `tracing::warn!` + emit `autopilot.tick_skipped` event to existing event bus (P1). No new table.
- Cron timezone: UTC only at v1. `cron_expr` stored as text. Parse-on-create rejects invalid expressions before insert.
- Next-tick calc cached: `autopilot.next_tick_at TIMESTAMP` column. Scheduler `ORDER BY next_tick_at ASC LIMIT 1` + wakes via `tokio::time::sleep_until`.
- Task enqueue: reuses P1's `TaskService::enqueue_task` with new `autopilot_run_id` optional field. **Single transaction** inserts `autopilot_run` + `agent_task_queue`.

## P7.3 — Scheduler thread + tick loop

**Crate:** `ainb-hangar-daemon` · **Module:** `crates/ainb-hangar-daemon/src/scheduler.rs` · **Estimate:** 1.5 day

**Deliverable:** tokio task that wakes at earliest `next_tick_at`, fires P7.4 enqueue, recomputes next tick.

```rust
pub struct AutopilotScheduler {
    pool: SqlitePool,
    clock: Arc<dyn HangarClock>,
    task_service: Arc<TaskService>,
    autopilot_service: Arc<AutopilotService>,
    shutdown: CancellationToken,
}

impl AutopilotScheduler {
    pub async fn run(self) -> Result<()> { /* select! over sleep_until + shutdown */ }
}
```

**Loop shape:**

```
┌──────────────┐    ┌──────────────────┐    ┌──────────────┐
│ pick earliest│───▶│ sleep_until tick │───▶│ fire enqueue │
│ next_tick_at │    │  OR shutdown     │    │ + reschedule │
└──────────────┘    └──────────────────┘    └──────┬───────┘
       ▲                                            │
       └────────────────────────────────────────────┘
```

If no enabled autopilots: sleep 60s then re-poll.

**Concurrency check at fire time:**

```rust
let in_flight = sqlx::query_scalar!(
    "SELECT count(*) FROM autopilot_run WHERE autopilot_id = ? AND completed_at IS NULL",
    autopilot_id
).fetch_one(&pool).await?;

if in_flight >= autopilot.max_concurrent_runs {
    tracing::warn!(autopilot_id = %autopilot.id, in_flight, "tick skipped — concurrency limit");
    emit_event("autopilot.tick_skipped", json!({ "autopilot_id": id, "reason": "concurrency" }));
    // still recompute next_tick_at + persist; don't fire enqueue
} else {
    p7_4_enqueue(...).await?;
}
```

**RED tests:**
```
test single_autopilot_fires_at_next_tick
test two_autopilots_fire_in_order
test skip_when_prior_run_in_flight (asserts no new agent_task_queue row + tick_skipped event)
test disabled_autopilot_skipped
test shutdown_token_exits_loop (within 100ms)
test recompute_uses_current_tick_not_clock_now (no drift)
```

**GREEN:** `tokio::select!` over `sleep_until(next_tick_at)` + `shutdown.cancelled()`. `tick_once()` pub-crate fn for test injection.

**Acceptance:**
- All 6 scheduler tests green
- No `tokio::time::sleep` without timeout-equivalent — all sleeps select with shutdown

## P7.4 — Autopilot task enqueue path

**Crate:** `ainb-hangar-core` · **Module:** `crates/ainb-hangar-core/src/autopilot/enqueue.rs` · **Estimate:** 0.5 day

**Deliverable:** single-tx fn that inserts `autopilot_run` + `agent_task_queue`:

```rust
pub async fn fire_autopilot_tick(
    pool: &SqlitePool,
    clock: &dyn HangarClock,
    autopilot: &Autopilot,
) -> Result<(AutopilotRunId, AgentTaskId)> {
    let mut tx = pool.begin().await?;
    let run_id = Ulid::new();
    sqlx::query!("INSERT INTO autopilot_run (id, autopilot_id, started_at, status) VALUES (?, ?, ?, 'running')",
                 run_id.to_string(), autopilot.id.to_string(), clock.now()).execute(&mut *tx).await?;
    let task_id = TaskService::enqueue_task_in_tx(&mut tx, EnqueueRequest {
        workspace_id: autopilot.workspace_id,
        agent_id:     autopilot.agent_id,
        autopilot_run_id: Some(run_id),
        instructions:  autopilot.instructions.clone(),
        kind:          TaskKind::Autopilot,
        ...
    }).await?;
    tx.commit().await?;
    Ok((run_id, task_id))
}
```

P1's `TaskService` gains `enqueue_task_in_tx` variant accepting existing `&mut Transaction`. Backward-compat: existing `enqueue_task` wraps in own tx.

**RED tests:**
```
test fire_creates_run_and_task_atomically       (both rows visible after commit; task.autopilot_run_id == run.id)
test fire_rolls_back_on_task_insert_failure     (agent_id FK violation; NO autopilot_run row persists either)
test task_kind_is_autopilot                     (agent_task_queue.kind == 'autopilot')
test run_completes_when_task_completes          (completing task with autopilot_run_id stamps autopilot_run.completed_at)
```

The 4th test exposes the **P1 cascade hook** — completing a task with `autopilot_run_id` populated also stamps `autopilot_run.completed_at`. Add this update inside `TaskService::complete_task` (same tx); inverse for `fail_task` (status='failed') and `cancel_task` (status='cancelled').

**GREEN:** single-tx insert helper + cascade update in TaskService finalize paths.

**Acceptance:**
- All 4 enqueue tests green
- `TaskService` cascade tested via existing P1 task lifecycle tests (re-run, must stay green)
- No double-commit / double-tx bugs

End-to-end with `FixedClock`:

```
1. boot daemon with FixedClock(t0=2026-01-01T00:00:00Z) + ephemeral SQLite
```

### Tripwire B: `tripwire_autopilot_skips_when_running.rs`

Concurrency policy:

```
1. boot daemon; create autopilot with max_concurrent_runs=1, cron="*/5 * * * *"
2. clock.advance(5min); wait for task #1 enqueued
3. do NOT complete task #1 (stays running)
4. clock.advance(5min); wait 1s
5. assert: NO new agent_task_queue row (count still == 1)
6. assert: autopilot_run table has 1 row (not 2)
7. assert: tracing event log captured "autopilot.tick_skipped" with reason="concurrency"
8. complete task #1
9. clock.advance(5min); assert task #2 enqueued normally
```

## Risks + mitigations

| Risk | Severity | Mitigation |
|------|----------|------------|
| `cron` crate edge cases differ from Multica's `robfig/cron` (Go) | Med | Tripwire A uses Multica's literal `"0 */6 * * *"` to confirm parity |
| Scheduler drift if `tick_once` fires late under load | Low | `next_tick_after(last_scheduled_tick, _)` — never reseed from `clock.now()` |
| Test isolation when 2 tripwires run in parallel | Med | `ENV_LOCK` + `tempdir` per test; cross-process pidfile |
| TaskService cascade update breaks existing P1 tests | High | Add cascade in same commit; re-run P1 task lifecycle tests before merge |
| `FixedClock` not honoured by `tokio::time::sleep_until` (real time vs injected) | High | scheduler uses `clock.now()` to compute sleep duration; test-only `clock_advance` admin RPC recomputes + skips sleep |
| User creates 100s of autopilots; index scan slow | Low | Partial index on `(workspace_id, enabled, next_tick_at) WHERE enabled = 1` |

## Open questions (escalate before P7.3 starts)

1. **Manual `run now` accounting:** does manually-triggered run count toward `max_concurrent_runs`? **Proposed:** yes — inserts `autopilot_run` row, scheduler sees as in-flight.
2. **`next_tick_at` in past at boot (daemon was down):** fire one catch-up tick immediately, then recompute forward from `clock.now()`. Do NOT replay every missed tick.
3. **Cron timezone:** UTC-only at v1 confirmed. Add `cron_tz TEXT` column in P7.x follow-up if requested.
