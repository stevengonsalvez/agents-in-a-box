# Hangar P0: Schema + crates skeleton

**Weeks:** W1-W2
**Beads:** `hangar:P0` (parent) + 7 sub-beads
**Builds on:** —
**Blocks:** P1 (daemon + FSM), P2 (beads sync), P3 (plugin caps), all downstream

## Goal

Land four empty-but-compiling crates (`ainb-hangar-core`, `ainb-hangar-store`, `ainb-hangar-proto`, `ainb-hangar-daemon`) under `ainb-tui/crates/`, wire `sqlx` + SQLite migrations that create all 14 v1 tables on first boot, and ship a daemon binary that boots to a no-op idle state and prints `--version`. No task lifecycle, no JSON-RPC handlers, no plugin caps — just the foundation every later phase plugs into. End-state user-visible proof: `ainb-hangar-daemon --version` works and `sqlite3 ~/.ainb/hangar.db ".schema"` lists `workspace`, `member`, `user`, `agent`, `agent_runtime`, `issue`, `comment`, `agent_task_queue`, `skill`, `skill_file`, `agent_skill`, `pat`, `daemon_token`, `beads_mapping`.

## Test fixtures + determinism

- **`HangarClock` trait** in `ainb-hangar-core` — `SystemClock` in prod; `#[cfg(test)] FixedClock(i64)` returns a frozen epoch-ms. Inject at `Store::open_in` via builder. Tests assert `task.created_at == fixed_ms`.
- **`IdGen` trait** in `ainb-hangar-core` — `SystemIdGen` returns `ulid::Ulid::new().to_string()`; `#[cfg(test)] FixedIdGen(Vec<String>)` pops from a pre-seeded queue (panics if exhausted). Mirrors `reference_msgpack_byte_determinism_vec_over_hashmap` discipline for repeatable golden assertions.
- **`with_isolated_home(f)`** in `ainb-hangar-store::test_support` — `tempfile::tempdir()` + `ENV_LOCK: Mutex<()>` + sets `AINB_HANGAR_HOME` for `f`'s duration. Mirrors `reference_env_lock_for_parallel_tests`.
- **Ephemeral SQLite** — every test uses `tempdir/hangar.db` (not `:memory:`) so WAL mode is exercised exactly like prod. Migrations run on each open.
- **No live `$HOME` mutation in tests.** Anything that touches env goes through `with_isolated_home`. CI's parallel `cargo test --test-threads=N` must stay green.

**Provides to next phase (P1 — daemon + FSM):**

- `ainb_hangar_core::TaskStatus` — the enum P1 will transition.
- `ainb_hangar_core::{HangarClock, IdGen}` — injection points for deterministic P1 FSM tests.

- `ainb-hangar-daemon` binary — P1 adds the FSM service + tmux launcher; nothing in P0 needs to change.

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Workspace adds `sqlx` (heavy dep tree) — first big DB dep in repo. | Med | Pin `default-features = false` + only `runtime-tokio-rustls`, `sqlite`, `macros`, `migrate`. Verify `cargo build -p ainb-hangar-store --offline` stays under +30s vs baseline. |

| Partial unique index syntax SQLite-vs-Postgres divergence later. | Low | The current `WHERE status IN ('queued','dispatched')` form is portable. Postgres migration in v2 will be byte-identical. |
| `ENV_LOCK` collisions across crates if any other test mutates `AINB_HANGAR_HOME`. | Low | Hangar's lock lives in `ainb-hangar-store::test_support`; no other crate should set `AINB_HANGAR_HOME`. Code-review gate. |
| `assert_cmd` not yet in workspace dev-deps. | Low | Add as a per-crate dev-dep in `ainb-hangar-daemon/Cargo.toml`; no workspace-wide change. |
| Existing `ainb-tui/Cargo.toml` `[workspace.lints]` block is strict (forbid `unsafe_code`, warn `missing_docs`). | Med | Plan accounts for it — every `pub` item gets a doc-comment in REFACTOR. Compile-fail if missed. |

## Rollback strategy

P0 is **schema-only + crates-only + new binary**. No production data writes anywhere (the binary is fresh, no users have it). Rollback = `git revert <merge-commit>` + nothing else. No data migration to unwind, no users to notify, no plugin SDK consumers (P3 hasn't started). Safe.

If post-merge a migration is found broken (e.g. typo in a CHECK constraint), forward-fix in a new migration `0006_fix_xxx.sql` rather than editing an applied one — preserves the `sqlx::migrate!` audit trail and matches Multica's discipline.
