# Hangar P8 — Kanban + Daemon health + observability polish

**Phase:** P8 · **Weeks:** 17-18 · **Sub-beads:** 7 · **Bead:** `hangar:P8`
**Builds on:** P0-P7 (instruments existing services + adds 2 TUI screens)
**Blocks:** P9 (release readiness gates on observability presence)

## Phase intent (caveman)

Day 1 for traces. DE warned: backfill OTEL into 50k LOC = pain. P8 wires tracing
NOW into every prior service span. Daemon main installs subscriber, JSONL
default sink, OTLP feature-flagged. Then ship last two screens: Kanban (4-col
horizontal board) + Daemon health (sparkline dual-dim per UX research). Logs
tail surface on both CLI + TUI. No new aggregates, no new tables — pure
instrumentation + view layer.

## Risks specific to P8

| Risk | Severity | Mitigation |
|------|----------|------------|
| OTLP crate version churn (opentelemetry 0.21 → 0.22 mid-phase) | Med | Pin exact versions in P8.2; bump only on intentional PR |
| Sparkline color glyphs differ across terminals (Term.app vs iTerm2 vs Linux) | Low | Tripwire uses ANSI escape grep, not glyph shape |
| JSONL appender holds file lock on Windows (we're Unix-only — non-risk) | None | Per ainb v1 platform decision, skip Windows entirely |
| Daemon shutdown leaves OTEL spans unflushed | Med | Explicit `shutdown_tracer_provider()` in daemon shutdown hook |
| `tracing::instrument` adds overhead to hot claim loop | Low | `skip_all` + `level = "debug"` on hot paths; benchmark in P9 |
