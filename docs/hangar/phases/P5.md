# Hangar Phase P5 — Auth + workspace + secret store (TDD plan)

**Phase:** P5 (Weeks 11-12)
**Epic:** hangar-v1
**Bead:** `hangar:P5`
**Sub-beads:** 6 (`P5.1 … P5.6`)
**Builds on:** P0 (schema: `pat`, `daemon_token`, `workspace`, `member`), P3 (plugin host caps incl. `host/secret_store_get`), P4 (Settings screen).
**Blocks:** P6 (templates need keychain-resident API keys at dispatch), P7 (autopilots use same key flow on schedule).
**Per-bead loop:** `claim → /plan-tdd → implement → code-reviewer → fix-same-run → tests → bd close`

## Decisions locked (from build-plan.md + DE critique)

- Secret store cap = `host/secret_store_get` only (read). Write path = host-side CLI / Settings screen — plugin never writes secrets.
- Backend mac = `security-framework` crate (Keychain Services). Backend linux = Secret Service stub returning `Err(NotImplemented)`. Backend tests = in-memory.
- Env policy = **allowlist not blocklist** (DE finding §6). Default 12 vars. User overrides via `~/.ainb/hangar/env.allow.toml`. **Hardcoded deny set** (`LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `PYTHONPATH`, `NODE_OPTIONS`, `BASH_ENV`, `ENV`, `GOPRIVATE`, `RUBYOPT`, `PERL5OPT`, `JAVA_TOOL_OPTIONS`) overrides any user allowlist entry — if user adds `LD_PRELOAD`, daemon refuses.
- Tokens: `ainb_` prefix for PAT (user→host); `mdt_` prefix for daemon tokens (daemon-to-daemon future). Storage = `sha256(token_plain)` only. Plain shown once at creation.
- Workspace switching = host-only state (lives in `~/.ainb/hangar/state.toml::active_workspace`). Plugin asks via `host/workspace_get_active`; rest of plugin caps already work on `(workspace_id, ...)` keys per P0.
- Danger-full-access warning = banner shown **once per session** at first provider invocation. Dismissal stored in `~/.ainb/hangar/state.toml::warnings_ack`.

## Default env allowlist (12 vars)

```
HOME PATH TERM LANG USER SHELL LC_* COLUMNS LINES CLAUDE_* CODEX_HOME ANTHROPIC_BASE_URL
```

API keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, …) are injected separately from keychain at exec time — **never** sourced from parent env. Allowlist governs only ambient env passthrough.

### P5.1 — OS keychain bridge crate (`ainb-hangar-secrets`)

**Owner:** backend-developer · **Deps:** P0 · **Estimate:** 0.5 day

**Artefacts:**
- new crate `ainb-tui/crates/ainb-hangar-secrets/` (lib only)
- `SecretBackend` trait: `get(scope, key) -> Result<Option<SecretBytes>>`, `put(scope, key, value)`, `delete(scope, key)`
- `MacKeychainBackend` (cfg `target_os = "macos"`, deps `security-framework = "2"`)
- `LinuxSecretServiceBackend` (cfg `target_os = "linux"`, returns `Err(NotImplemented)`)
- `InMemoryBackend` (gated `#[cfg(any(test, feature = "test-backend"))]`)
- `SecretBytes` newtype with `Zeroize` on drop
- `Scope` enum: `Workspace(WorkspaceId)`, `Global`

**RED tests** (`crates/ainb-hangar-secrets/tests/`):
1. `get_missing_returns_none()` — fresh backend, `.get(scope, "anthropic_api_key")` → `Ok(None)`
2. `put_then_get_roundtrips()` — `.put(scope, "k", b"v")`, `.get(scope, "k")` → `Ok(Some(b"v"))`
3. `delete_then_get_returns_none()` — round-trip-then-delete sequence
4. `scopes_are_isolated()` — same key, different workspace scopes, must not bleed
5. `secret_bytes_zeroizes_on_drop()` — use `zeroize::Zeroizing` invariant test
6. `mac_backend_uses_correct_service_string()` — assert service = `ainb-hangar::{scope_id}`
7. `linux_backend_returns_not_implemented()` — explicit `assert!(matches!(err, SecretError::NotImplemented))`

**GREEN:** Minimum wrapper around `security-framework::passwords::{set,find,delete}_generic_password`. No keychain access groups (single-user mac).

**Acceptance:**
- `cargo test -p ainb-hangar-secrets` green
- `cargo clippy -p ainb-hangar-secrets -- -D warnings` clean
- Manual: `security find-generic-password -s 'ainb-hangar::local'` returns the test entry after a roundtrip test on a dev mac

**Failure modes:** keychain locked → `Err(BackendLocked)`; user denies prompt → `Err(AccessDenied)`. Distinct so daemon UX can recover.

### P5.3 — Env allowlist enforcement + CLI

**Owner:** backend-developer · **Deps:** P0, P1 · **Estimate:** 1.5 day

**Artefacts:**
- `ainb-hangar-core::env_policy` module: `EnvPolicy { allow: BTreeSet<String>, deny_hardcoded: &'static [&'static str] }`

- CLI verbs:
  - `ainb hangar config env.allow list|add <KEY>|remove <KEY>`
- daemon wiring: `daemon::dispatch::build_task_env()` calls `apply_policy` AFTER keychain key injection

**RED tests:**
1. `default_allowlist_passes_through_home_path_term()` — 12 defaults, no `MULTICA_*` survives, no `RUST_LOG`
2. `hardcoded_deny_overrides_user_allow_for_ld_preload()` — user adds `LD_PRELOAD`; assert still stripped, warn logged
3. `hardcoded_deny_overrides_for_dyld_insert_libraries()` — macOS variant
4. `hardcoded_deny_overrides_for_pythonpath_node_options_bash_env()` — parametrised `rstest` table
5. `glob_pattern_lc_underscore_star_matches()` — `LC_*` matches `LC_ALL`, `LC_CTYPE`, etc.
6. `cli_add_writes_atomically_and_roundtrips_toml()` — pre-existing `[other_plugin]` section survives
7. `tripwire_env_allowlist_blocks_ld_preload.rs` — full daemon dispatch with `LD_PRELOAD=/tmp/evil.dylib`; spawned subprocess env does NOT contain the key
8. `tripwire_env_allowlist_passes_home.rs` — opposite assertion

**GREEN:** Simple `BTreeSet` lookup + glob match for `*` suffix + hardcoded deny check (always second pass). No regex. `const DENY: &[&str]` in `env_policy.rs`.

**Acceptance:**
- DE finding reversed: deny is hardcoded, allow is configurable, allow cannot override deny
- `ainb hangar config env.allow list` shows merged effective set with `[deny-locked]` suffix
- Both tripwires green; tests parallel-safe via `apply_policy(input_map)` (no `std::env::set_var`)

4. `daemon_token_format_starts_with_mdt_prefix()`
5. `verify_accepts_minted_plain()` — round-trip
6. `verify_rejects_tampered_plain()` — flip one char, None
7. `verify_uses_constant_time_compare()` — compile-time check via `cargo expand` snapshot
8. `revoke_marks_record_and_verify_returns_none()`
9. `cli_token_create_prints_plain_then_warns_no_second_chance()` — stdout includes warning
10. `cli_token_list_does_not_print_plain()` — only id, prefix, timestamps

**GREEN:** `getrandom` + `sha2` + `subtle` + `base32`. SQLite UPSERTs via sqlx.

## Risk register

| Risk | Severity | Mitigation |
|---|---|---|
| `security-framework` blocks on user keychain prompt during tests | Med | InMemoryBackend for unit tests; mac integration tests gated `#[ignore]` + manual; CI never touches real keychain |
| New cap variants break exhaustive matches | Med | Propagate per `reference_gated_by_variant_propagation`; forbid wildcards; CTS regen in same commit |
| env mutation in tests races under parallel cargo test | Low | `apply_policy` takes input map; no `std::env::set_var` in test bodies |
| Tripwire tmux capture-pane brittle | Low | `vhs sleep budget × 1.3` per `reference_vhs_sleep_budget`; substring not snapshot |
| Plain token accidentally logged | High | `slog::Value` impl on `PlainToken` returns `"<redacted>"`; CI grep rule for `ainb_[A-Z2-7]` in logs/ |
| User adds `LD_PRELOAD` to allowlist and assumes it works | Med | Hardcoded deny + warn log + CLI `add` rejects with explanatory error before write |
| Daemon process can't read keychain when launched from launchd | Med | Document; surface `BackendLocked` via warning banner in Settings; defer launchd integration to P9 |
| Linux Secret Service stub leaves users without secret store | Accepted | Dotenv fallback documented; explicit follow-up bead `hangar:P5.X-future-linux` |
