# Hangar P2 — Beads Sync Adapter (TDD plan)

**Phase:** P2 (Weeks 5-6)
**Epic:** `hangar-v1`
**Parent bead:** `hangar:P2`
**Sub-beads:** 6 (`hangar:P2.1` … `hangar:P2.6`)
**Builds on:** P0 (schema + `beads_mapping` table) · P1 (task FSM + services)
**Unblocks:** Stevie's daily loop — bd UX stays live while Hangar backfills

## Why this phase

Beads = Stevie's existing issue tracker. Hangar = new task table. Killing
either kills daily flow. P2 = mirror, not replace. Two-way sync, last-writer-
wins, periodic reconcile. Adapter lives in `ainb-hangar-daemon`, repo lives in
`ainb-hangar-store`, CLI surface lives in `ainb-hangar-core::cli`.

## Locked decisions (do not re-litigate)

- Sync model = **two-way, last-writer-wins** per `last_synced` timestamp
- Adapter = shell out to `bd` CLI, parse `--json`. No bd library link.
- Mapping table = `beads_mapping (hangar_id, bd_id, hangar_kind, bd_kind, last_synced)` (P0)
- Inbound = daemon thread polling `bd list -l hangar-v1 --json` every 30s
- Outbound = hooked into `IssueService::create` / `IssueService::close` (P1)
- Reconcile = `ainb hangar beads reconcile` walks mapping, fixes drift
- Polymorphic assignee — bd has `assignee:String`, Hangar has `(actor_type,
  actor_id)`. Mapping crosswalks: agent IDs prefixed `agent:`, user IDs raw.
- **`BEADS_DIR` must be set explicitly when in a worktree** (per
  `reference_beads_worktree`). Daemon reads `BEADS_DIR` env, fails fast if
  unset and `pwd` isn't a beads root.
- **Don't fight swarm-leader bd ownership** (per
  `feedback_swarm_leader_owns_bd_tracking`). Hangar→bd sync is for
  user-created Hangar issues only; tasks spawned by a swarm leader retain
  leader's bd lifecycle. Mapping carries `source: hangar | swarm` flag —
  swarm-sourced rows skip outbound mirror.

## Architecture sketch

```
┌─────────────────────┐  create   ┌──────────────────┐  bd create
│ ainb hangar issue   │──────────▶│ IssueService     │──────────▶ bd CLI
│ create              │           │  ::create        │             │
└─────────────────────┘           │  (P1)            │             ▼
                                  └──────────────────┘        beads_mapping
                                          │                    INSERT row
                                          ▼
                                  ┌──────────────────┐
                                  │ BeadsSyncAdapter │
                                  │  ::outbound      │
                                  └──────────────────┘

┌─────────────────────┐  poll 30s  ┌──────────────────┐  reconcile
│ daemon thread       │──────────▶│ BeadsSyncAdapter │──────────▶ IssueService
│ inbound_loop        │           │  ::inbound       │              │
└─────────────────────┘           └──────────────────┘              ▼
                                          │                   issue.status=done
                                          ▼
                                  beads_mapping
                                  UPDATE last_synced
```

   - seed: mapping row + open Hangar issue
   - fake-bd `list` returns issue with `status: closed`
   - call `InboundSync::reconcile_once()`
   - assert: Hangar issue status = done, mapping `last_synced` bumped
2. `test_bd_status_change_updates_hangar_status`

   `CancellationToken::cancel()`, assert loop exits within 1s
7. `test_poll_loop_backoff_on_bd_failure` — fake-bd exits 1; loop logs
   error, sleeps `next_interval = min(prev * 2, 5min)`, retries

**GREEN — implementation:**

```rust
pub struct InboundSync<'a> { /* same deps as Outbound */ }

impl<'a> InboundSync<'a> {
    pub async fn reconcile_once(&self) -> Result<ReconcileStats, SyncError>;
}

pub async fn run_inbound_loop(
    sync: Arc<InboundSync<'static>>,
    interval: Duration,        // default 30s
    cancel: CancellationToken,
) {
    let mut delay = interval;
    loop {
        tokio::select! {
            _ = cancel.cancelled() => break,
            _ = tokio::time::sleep(delay) => {}
        }
        match sync.reconcile_once().await {
            Ok(_)  => { delay = interval; }
            Err(_) => { delay = (delay * 2).min(Duration::from_secs(300)); }
        }
    }
}
```

- Filter: `bd list -l hangar-v1 --json` — only issues tagged for sync
- Loop spawned as named `JoinHandle` registered with daemon's supervisor
  for restart-safety

**REFACTOR:**

- `ReconcileStats { scanned, updated, skipped, errors }` — useful for the
  `reconcile` command in P2.5
- Pull `bd list filter` into a typed `BdListFilter { labels: Vec<String>, since: Option<DateTime<Utc>> }`

**Acceptance:** Tripwire: start daemon, fake-bd flips an issue closed,
within 1s loop tick the Hangar issue is `done`.

## Cross-cutting concerns

### `BEADS_DIR` discipline

- Daemon reads `BEADS_DIR` once at startup; logs the resolved path at INFO
- All `BdClient` invocations pass it explicitly (no PWD reliance)
- Tests **always** set `BEADS_DIR=$tempdir` — no relying on caller cwd
- Per `reference_beads_worktree`: doc string on `BdClient::new` warns
  worktree callers must set explicitly.

### Polymorphic assignee crosswalk

Bidirectional table (single source of truth in `assignee_crosswalk` module):

| Hangar `(Actor::Agent, "ag_x")` | bd `agent:ag_x` |
| Hangar `(Actor::User,  "stevie")` | bd `stevie` |
| Hangar `None` | bd `` (unassigned) |

Round-trip property test:
`prop_assert_eq!(bd_to_hangar(hangar_to_bd(x)), x)` for all `x`.

### Swarm-leader bd ownership boundary

Per `feedback_swarm_leader_owns_bd_tracking`:

- `Issue.source: IssueSource { Hangar, Swarm }`
- Outbound mirrors **only** `Hangar`-sourced issues
- Inbound reconciles **only** mappings where `source = Hangar`
- Swarm leader's bd lifecycle remains untouched — no double-write

Tripwire P2.6 explicitly seeds one `Swarm`-sourced issue to assert
adapter ignores it.

### Failure mode handling

| Failure | Behaviour |
|---|---|
| `bd` not installed | `BdClient::new` returns err; daemon logs WARN, sync disabled, hangar still works |
| `bd` command exits nonzero | Mapping row `pending_sync=true`, retried by reconcile |
| sqlite write conflict | sqlx retry with backoff (P0 wired this) |
| Daemon crashes mid-sync | On restart, `pending_sync=true` rows reprocessed before resuming inbound loop |
| Clock skew between bd commit time + Hangar `now()` | `last_synced` always wall-time from `HangarClock`; bd timestamps used only as advisory |

## Risks + mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| bd CLI shape changes between local versions | Med | Pin minimum `bd --version` at daemon start; fail fast with clear msg |
| sqlite + bd both writing to git in worktree race | Low | O_EXCL pidfile in `BdClient` (P2.2) serialises bd writes; sqlite is its own file |
| Reconcile loop runs hot if interval misconfigured | Low | Min interval clamped to 5s in config validator |
| Inbound loop holds db connection forever | Low | Per-tick `pool.acquire().await` then drop; never hold across `tokio::sleep` |
| User assignee string collides with `agent:` prefix | Low | Validate user IDs at issue create time — reject literal `agent:` prefix |
| Tripwire requires real bd binary | Med | Skip-with-hint when absent; CI matrix has bd by default |
