# Hangar P3 — Plugin host caps + hangar-tui plugin scaffold

**Phase:** P3 (Weeks 7-8) · **Sub-beads:** 8 · **Bead label:** `hangar`, `hangar-v1`, `phase:P3`
**Builds on:** P1 (daemon dialable on `~/.ainb/hangar.sock`)
**Blocks:** P4 (Core 5 TUI screens needs plugin scaffold)
**Owner:** swarm wave P3 · **Mode:** TDD per bead

## Goal

Land 4 new host caps in plugin host v2 + scaffold empty `hangar-tui` plugin. Plugin
boots inside `ainb tui`, dials daemon socket via cap, subscribes to `workspace:default`,
renders stub "Hangar: Connected" footer. CTS extended with 4 new axes. No screens yet
(P4 owns Core 5).

## Caveman map


| `host/secret_store_get` | plugin -> host | read mac Keychain / linux Secret Service |

## Critical refs

- `project_ainb_plugin_cts_patterns` — JSON-RPC method catalogue locked. Cap gating
  enforced at *runtime* dispatcher with `-32001 CAPABILITY_DENIED`, never by omitting
  from method registry. UUID names + sentinel logs for anti-cheat.
- `reference_ainb_plugin_v2_architecture` — Native subprocess + JSON-RPC 2.0 over
  Content-Length stdio. TOML manifest. Language-agnostic.
- `reference_plugin_sdk_no_host_deps` — protocol crate stays pure; no ratatui /
  tokio / host crate re-exports leaking through SDK.
- `reference_gated_by_variant_propagation` — new cap variants break exhaustive
  matchers in plugin-runtime + plugin-cts-v2. Propagate to every match site. Forbid
  wildcard arms; CI catches via `-D warnings`.

## TDD principles

**Per cap:**
1. RED: protocol crate — `params.rs` round-trip test for new `<Method>Params`/`Result`.
2. RED: protocol crate — `methods.rs` registry test asserts new const in `ALL_METHODS`.
3. RED: CTS canary axis test asserts cap omitted -> `-32001` returned, cap granted ->
   handler reached + sentinel log emitted.
4. RED: runtime unit test asserts dispatcher routes method to handler.
5. GREEN: minimal handler + dispatcher wiring.
6. REFACTOR: extract shared cap-gate macro / helper if 4+ handlers duplicate.

**Anti-cheat (per CTS patterns memory):** each canary uses UUID-suffixed plugin name +
emits sentinel log on cap-allowed path. Host-side test reads sentinel from
`host/log` channel; absence = cap silently bypassed.

```
host/event_stream_subscribe          -> { stream_id: String, version: u64 }
```

### P3.2 — `host/event_stream_subscribe` runtime impl + CTS axis A15

**Title:** `hangar:P3.2 event_stream runtime + CTS A15`
**Files:**
- `ainb-tui/crates/ainb-plugin-runtime/src/rpc.rs` (dispatcher arm)
- `ainb-tui/crates/ainb-plugin-runtime/src/plugin_task.rs` (per-plugin stream set,
  drop on FSM leave Running)
- `ainb-tui/crates/ainb-plugin-runtime/src/snapshot.rs` (extend to broadcast
  stream events to subscribed plugins by topic)
- `ainb-tui/crates/ainb-plugin-cts-v2/tests/canaries/a15_event_stream_subscribe/main.rs`
- `ainb-tui/crates/ainb-plugin-cts-v2/tests/axes.rs` (new `a15_*` test)

**Canary behaviour:**
1. Plugin manifests `event_stream_subscribe = ["workspace:*"]`.
2. On `plugin/init`, plugin calls `host/event_stream_subscribe` with topic
   `workspace:cts-canary-<UUID>`.
3. Host publishes 3 sentinel events via test fixture.
4. Plugin captures each `plugin/handle_event` with matching `stream:` topic prefix,
   emits `host/log` `"SENTINEL_RX_<n>"` per event.
5. On 4th event, plugin sends `host/event_stream_cancel`. Host fixture sends a 5th
   event; canary asserts none received via timeout.

**Host-side test asserts:**
- 3 sentinel log lines captured (anti-cheat: cap-allowed handler actually ran).
- Cancellation honoured: no `SENTINEL_RX_5` after timeout.
- Cap-omitted manifest variant: subscribe returns `RpcError::CAPABILITY_DENIED` (-32001),
  no events delivered.
- Plugin restart while subscribed: host drops stream, no events leak.

**Critical impl detail:**
- Stream IDs are host-allocated `ulid` strings. Plugin-side cannot forge.
- Topic whitelist enforced post-method-dispatch via cap allow-list (list form).
  Bool-true grant = wildcard; list = prefix-match.

- `ainb-tui/crates/ainb-plugin-cts-v2/tests/axes.rs`

**Contract:**
```
host/spawn_managed_subprocess
  params: { bin: String, argv: Vec<String>, env_allowlist: Vec<String>, cwd?: String }
  result: { handle: String, pid: u32 }
```

**Lifecycle (host owns supervision):**
- Host enforces bin path is on cap allow-list (list-form mandatory; bool-true rejected
  at manifest validation).
- Host spawns under pgrp/job-object — same leak guard as plugin process. On Runtime
  drop or plugin shutdown, host kills all managed subs.
- `env_allowlist` filters parent env to listed names + manifest-declared defaults
  (per `feedback_agent_owns_ops` + security decision round 4).
- Plugin gets `handle` back; subsequent `host/event_stream_subscribe` on topic
  `managed:<handle>:stdout` streams subprocess output (composes with P3.2).

**RED tests:**
- Cap denied: -32001 + no fork.
- Bin not on whitelist: `RpcError::CAPABILITY_DENIED` with `data.bin` = attempted path.
- Env filtering: spawned child sees only allow-listed vars (canary `printenv` then
  hashes + compares).
- Reap on plugin shutdown: pid no longer alive within 2s of `plugin/shutdown`.

**Caveman note:** this is the cap hangar-tui plugin uses to spawn `ainb-hangar-daemon`
on first run when daemon not already up. P1 daemon binary in `~/.cargo/bin/` (or
discovered via `which`); manifest whitelist: `["ainb-hangar-daemon"]`.

**Acceptance:**
- [ ] CTS A16 green

### P3.4 — `host/unix_socket_dial`

**Title:** `hangar:P3.4 host/unix_socket_dial + CTS A17`
**Files:**
- protocol crate: same trio
- `ainb-tui/crates/ainb-plugin-runtime/src/rpc.rs`
- new module: `ainb-tui/crates/ainb-plugin-runtime/src/unix_socket.rs` (per-plugin
  dial registry, read/write/close via JSON-RPC stream events)
- `ainb-tui/crates/ainb-plugin-cts-v2/tests/canaries/a17_unix_socket_dial/`

**Contract:**
```
host/unix_socket_dial
  params: { path: String }
  result: { stream_id: String }

host/unix_socket_send (notification)
  params: { stream_id: String, bytes: Bytes }

# host -> plugin events via plugin/handle_event topic "socket:<stream_id>"
# Payloads are { kind: "data"|"eof"|"error", bytes?, error? }

host/unix_socket_close (notification)
  params: { stream_id: String }
```

**Whitelist enforcement (CRITICAL):**
- Cap MUST be list-form. Bool-true grant rejected at manifest validation
  (`MANIFEST_VALIDATION` -32003) — no wildcard unix dials. Defends against arbitrary
  AF_UNIX abuse on shared dev boxes.
- Path canonicalized + compared against list entries. Symlink resolution before
  compare to prevent `~/.ainb/hangar.sock` symlinked to `/var/run/docker.sock` attack.
- Hangar's manifest whitelists exactly one path:
  `["${XDG_RUNTIME_DIR}/ainb-hangar.sock", "~/.ainb/hangar.sock"]` (env vars
  expanded by host, not plugin).

**Lifecycle:**
- Streams cancelled on plugin restart / shutdown (same machinery as P3.2).
- Host buffers up to N=64KiB unread bytes per stream; backpressures plugin via
  blocking notification ack (not yet — note as TODO P5 if it becomes a problem).

**RED tests:**
- Cap denied (bool false / list empty): -32001.
- Bool-true grant: manifest validation rejects.
- Path not on whitelist: -32001 with `data.path`.
- Symlink attack: dial via symlink that resolves outside whitelist -> denied.
- Plugin restart mid-stream: host closes socket; sentinel log host-side.

**Acceptance:**
- [ ] CTS A17 green
- [ ] Symlink + path canonicalization unit-tested
- [ ] `bd close hangar:P3.4`

### P3.5 — `host/secret_store_get` (mac Keychain; linux stub)

**Title:** `hangar:P3.5 host/secret_store_get + CTS A18`
**Files:**
- protocol crate trio
- new module: `ainb-tui/crates/ainb-plugin-runtime/src/secret_store.rs`
- `ainb-tui/crates/ainb-plugin-runtime/Cargo.toml` — add `security-framework`
  (mac only, target-gated)
- `ainb-tui/crates/ainb-plugin-cts-v2/tests/canaries/a18_secret_store_get/`

**Contract:**
```
host/secret_store_get
  params: { service: String, account: String }
  result: { secret_b64: String }
  errors: -32001 cap denied | -32004 SECRET_NOT_FOUND | -32005 NOT_IMPLEMENTED
```

**New error codes (in `errors.rs`):**
```rust
pub const SECRET_NOT_FOUND: i32 = -32004;
pub const NOT_IMPLEMENTED: i32 = -32005;
```

**Platform split:**
- darwin: `security_framework::passwords::get_generic_password(service, account)`
- linux: returns `RpcError::new(NOT_IMPLEMENTED, "linux Secret Service deferred to P5")`.
  Compile target-gated; the linux build of the runtime ships the stub returning -32005
  so the cap exists, contract is honoured, but the user gets a clean error and can fall
  back to dotenv per `build-plan.md` Open Risks row 4.

**Cap allowlist form:**
- List = whitelist of `service` strings (e.g. `["ainb-hangar", "anthropic-api-key"]`).
- Bool-true = unconditional grant (allowed but flagged: per
  `feedback_options_with_negative_impacts`, document the negative impact in PR body —
  unrestricted secret read is a danger surface).

**RED tests:**
- darwin: seed keychain via `security_framework` in test setup; assert read returns
  bytes matching seed. Cap denied -> -32001. Service not on whitelist -> -32001.
  Service on whitelist but absent -> -32004.
- linux (gated `#[cfg(target_os = "linux")]`): assert -32005 returned.
- Anti-cheat: sentinel log `SECRET_READ_OK_<UUID>` only emitted on actual keychain
  hit, not stub path.

**CI matrix concern:** keychain access on macOS CI requires unlocked login keychain
*or* a per-test ephemeral keychain. Use `security_framework`'s `SecKeychain::create` +
`unlock` pattern; tear down in test drop. Linux CI runs the stub-asserting test.

**Acceptance:**
- [ ] CTS A18 green on darwin (real keychain) + linux (stub)

### P3.8 — Tripwire: e2e plugin↔daemon roundtrip

**Title:** `hangar:P3.8 tripwire_hangar_plugin_connects`
**Files:**
- `plugins/hangar-tui/tests/tripwire_hangar_plugin_connects.rs`

**Layout (paste-ready skeleton):**
```rust
//! Tripwire: spawn ainb-hangar-daemon + ainb tui (which loads hangar-tui plugin)
//! inside tmux. Drive nothing; just assert the footer shows "Hangar: Connected"
//! within a deterministic budget.

use std::time::Duration;

#[test]
fn tripwire_hangar_plugin_connects() {
    let home = setup_isolated_home();          // tempdir, $HOME override
    let socket = home.path().join(".ainb/hangar.sock");

    let daemon = spawn_daemon(&home, &socket); // ainb-hangar-daemon --socket=...
    poll_socket_ready(&socket, Duration::from_secs(5));

    let tmux_session = format!("hangar-tripwire-{}", std::process::id());
    spawn_ainb_tui_in_tmux(&tmux_session, &home);

    // 30s budget per reference_vhs_sleep_budget (real-$HOME cold paint).
    poll_tmux_for(&tmux_session, "Hangar: Connected", Duration::from_secs(30));

    // Teardown by named session ONLY (tmux_protection).
    tmux_kill_session(&tmux_session);
    daemon.kill();
}
```

**Helpers required:**
- `setup_isolated_home`: tempdir + `HOME=` env override; copy minimal ainb config
  + skip onboarding.
- `spawn_daemon`: uses `CARGO_BIN_EXE_ainb-hangar-daemon`.
- `spawn_ainb_tui_in_tmux`: `tmux new-session -d -s $name 'ainb tui'`. Critical:
  named session, never wildcards.
- `poll_tmux_for`: `tmux capture-pane -p -t $name` + substring assert, 200ms sleep
  per poll.

**Determinism guards:**
- Inject `HangarClock` trait + ulid generator (per build-plan round 4 decision).
- `BU_NAME`-style env var so parallel tripwires don't collide on socket path.
- Cap socket dial whitelist includes the tempdir path (host expands `${HOME}` per
  P3.4 contract).

**Anti-flake:**
- `cross_process_test_serialization` per `reference_cross_process_test_serialization`
  — O_EXCL pidfile + stale-PID steal. Prevents two tripwires racing for tmux session
  names that collide.

**Acceptance:**
- [ ] `cargo test -p ainb-plugin-hangar --test tripwire_hangar_plugin_connects` green
  on darwin + linux
- [ ] Failure injection sanity: stop daemon mid-test, assert tripwire detects
