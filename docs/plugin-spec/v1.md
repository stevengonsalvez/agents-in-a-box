# ainb plugin contract — v1

**Status**: stable.
**Host versions covered**: `1.1.0`, `1.x.y` (additive minor bumps stay in v1).
**Successor**: tracked under `docs/plugin-spec/CHANGELOG.md`. A new contract version (`v2`) only ships when an existing signature changes incompatibly.

A plugin **conforms to v1** if it satisfies every MUST clause below. The
`ainb-plugin-cts` crate is the executable form of this document — a
plugin author runs it via `cargo test` to get a per-axis pass/fail
report. This file plus the matching `crates/ainb-plugin-cts/spec/v1/contract.toml`
(machine-readable signature vectors) are the source of truth.

## 1. Manifest

A plugin's `plugin.toml` MUST parse as the `Manifest` struct exported by
`ainb-plugin-api`:

```toml
[plugin]
name             = "my-plugin"   # required, unique within a host process
version          = "0.1.0"       # required, semver
ainb_min_version = "1.1.0"       # required, semver — minimum host ABI
description      = "..."         # optional
author           = "..."         # optional
license          = "..."         # optional
homepage         = "..."         # optional

[capabilities]                   # all flags default to false / [].
read_sessions     = false        # ~/.claude/agents-in-a-box/sessions/**
write_plugin_data = false        # ~/.agents-in-a-box/plugins/data/<id>/
event_bus         = false        # publish/subscribe across plugins
read_claude_logs  = false        # ~/.claude/projects/**/*.jsonl
read_codex_logs   = false        # ~/.codex/logs/**/*.jsonl
spawn_subprocess  = false        # exec child processes
network           = []           # explicit allowlist of "host:port" entries
filesystem        = []           # explicit allowlist of glob patterns

[provides]                       # purely informational; defaults are [].
screens    = []
commands   = []
sidebar    = []
statusline = []
providers  = []
```

* MUST: `[plugin].name`, `[plugin].version`, `[plugin].ainb_min_version`.
* MUST: `version` and `ainb_min_version` parse as semver.
* MAY: any of the optional `[plugin]` keys.
* MAY: any of `[capabilities]` and `[provides]`.

The host enforces capabilities by linker omission (a plugin that
declares `network = []` does not get `ainb_http_request` linked into
its imports — calling it produces a wasmi instantiation failure, not a
runtime trap).

## 2. ABI exports

A plugin MUST be a `wasm32-wasip1` cdylib exporting these symbols:

| Export | Signature | Required? | When called |
|---|---|---|---|
| `_init` | `() -> i32` | required | Once at load. `0` = ok; non-zero degrades the plugin. |
| `_render` | `() -> i32` | optional | Per frame for screen-owning plugins. |
| `_tick` | `() -> i32` | optional | Per ainb tick (host scheduler decides cadence). |
| `_handle_event` | `(ptr: i32, len: i32) -> i32` | optional | Whenever the host dispatches a `PluginEvent` (msgpack). |
| `_shutdown` | `() -> ()` | optional | Best-effort, called once on host shutdown. |
| `_alloc` | `(size: i32) -> i32` | optional | Host-side allocator: returns a guest-memory pointer. Required iff the plugin handles events. |

### 2.1 Lifecycle ordering

The host MUST observe:

1. `_init` runs exactly once before any of `_render` / `_tick` / `_handle_event`.
2. `_init` returning non-zero marks the plugin failed; no further
   exports are called for that plugin.
3. `_shutdown` runs at most once, after every other call has returned.
4. A trap (panic) inside `_render` / `_tick` marks the plugin
   *degraded*; subsequent calls are no-ops returning `Ok(())`. The plugin
   stays loaded — the host MUST NOT reload or restart it within the
   same process.
5. A trap inside `_handle_event` marks the plugin degraded the same way.

### 2.2 `_handle_event` payload

`(ptr, len)` MUST point into the plugin's own linear memory. The host
calls `_alloc(len)` first, writes the msgpack payload at the returned
offset, then calls `_handle_event(ptr, len)`. The plugin MUST decode
the bytes with the same `PluginEvent` schema `ainb-plugin-api`
exports:

```rust
pub enum PluginEvent {
    Custom { topic: String, payload: serde_json::Value },
    Command { name: String, args: Vec<String> },
    // future variants are append-only.
}
```

External tagging (`#[serde(rename_all = "snake_case")]`) — internally-tagged
enums are forbidden in this contract because rmp-serde rejects
internally-tagged primitive newtypes.

## 3. Host functions

The host imports live in module `ainb` (or `env` for legacy plugin
authors). All `(ptr, len)` arguments point into guest memory; the host
copies in/out across the boundary. Capability gates are enforced at
link time — calling a function the manifest doesn't approve produces
an instantiation failure, NOT a runtime trap.

| Function | Signature | Capability | Purpose |
|---|---|---|---|
| `ainb_log` | `(level: i32, ptr: i32, len: i32) -> ()` | none | Forward a log line at the given tracing level. |
| `ainb_now_ms` | `() -> i64` | none | Wall-clock millis since UNIX epoch. |
| `ainb_render_buffer` | `(target: i32, ptr: i32, len: i32) -> ()` | none | Hand the host a serialised `WireBuffer`. `target=0` Screen, `target=1` Sidebar, `target=2` Statusline. |
| `ainb_fs_read` | `(ptr: i32, len: i32) -> i32` | `filesystem` (one of the declared globs must match) | Read a file. Returns guest-memory ptr or 0 on error. |
| `ainb_fs_glob` | `(ptr: i32, len: i32) -> i32` | `filesystem` | Glob → list of paths (msgpack-encoded). |
| `ainb_data_read` | `(key_ptr, key_len, out_ptr, out_cap) -> i32` | `write_plugin_data` | Read from `data/<id>/` KV store. |
| `ainb_data_write` | `(key_ptr, key_len, val_ptr, val_len) -> i32` | `write_plugin_data` | Write to `data/<id>/` KV store. |
| `ainb_event_publish` | `(topic_ptr, topic_len, payload_ptr, payload_len) -> i32` | `event_bus` | Queue an event for delivery on the next pump. |
| `ainb_event_subscribe` | `(topic_ptr: i32, topic_len: i32) -> i32` | `event_bus` | Subscribe to a topic. |
| `ainb_session_get` | `(id_ptr, id_len, out_ptr, out_cap) -> i32` | `read_sessions` | Read one session by id. |
| `ainb_sessions_list` | `(out_ptr: i32, out_cap: i32) -> i32` | `read_sessions` | List sessions ids. |
| `ainb_http_request` | `(req_ptr, req_len, resp_ptr, resp_cap) -> i32` | `network` (host:port allowlist enforced inside the host fn) | HTTPS request. |

`wasi_snapshot_preview1` imports (`fd_write`, `fd_close`, `clock_time_get`,
`environ_get`, `environ_sizes_get`, `proc_exit`, `random_get`,
`fd_fdstat_get`, `fd_filestat_get`, `fd_prestat_get`,
`fd_prestat_dir_name`, `fd_read`, `fd_seek`, `path_filestat_get`,
`path_open`, `path_readlink`) are stubbed for compatibility — Rust's
panic handler links them but the host doesn't actually read or write
through them. Plugins MUST use the `ainb_*` family for I/O.

## 4. Wire types

### 4.1 `WireBuffer`

```rust
pub struct WireBuffer {
    pub width:  u16,
    pub height: u16,
    pub cells:  Vec<WireCell>,   // length MUST equal width * height
}

pub struct WireCell {
    pub symbol:    String,       // single grapheme cluster
    pub fg:        u8,           // 8-bit ANSI; 0xFF = inherit/default
    pub bg:        u8,
    pub modifiers: u8,           // bitfield: BOLD=1, DIM=2, ITALIC=4, UNDERLINED=8, REVERSED=16
}
```

The host MUST validate `cells.len() == usize(width) * usize(height)`
and reject buffers that fail. `width = 0` or `height = 0` MUST be
treated as a no-op render rather than a hard error — a plugin that
hasn't laid out its buffer for the current frame can hand back an
empty buffer without crashing the host.

### 4.2 `RenderTarget`

```rust
pub enum RenderTarget {
    Screen    = 0,
    Sidebar   = 1,
    Statusline = 2,
}
```

## 5. Resource budgets

| Budget | Limit | Enforcement |
|---|---|---|
| Per-call wall time (`_render` / `_tick` / `_handle_event`) | 50ms | wasmi fuel: tick / render calls run with a fixed fuel budget; exhaustion traps the call and the host marks the plugin degraded. |
| Buffer payload (`ainb_render_buffer`) | 64 KiB | Validator in `ainb_render_buffer` rejects oversized payloads. |
| Event payload (`ainb_event_publish`) | 64 KiB | Validator in `ainb_event_publish` rejects oversized payloads. |
| `_alloc` request size | 1 MiB | Host MAY refuse and fail the dispatch if the plugin asks for more. |
| Plugin static memory | wasmi default (4 GiB max addressable; the actual cap is OS RAM) | wasmi caps per-instance memory growth. |

A plugin SHOULD return promptly from any per-frame call. A host
implementation MAY use a smaller per-call budget; a plugin MUST NOT
assume more than 50ms.

## 6. Error semantics

* **Fatal** (whole plugin disabled): `_init` returns non-zero or traps;
  capability check fails at instantiation; manifest fails to parse.
* **Degrading** (plugin marked degraded; loaded but skipped): trap or
  non-zero return from `_render` / `_tick` / `_handle_event`.
* **Recoverable** (single call rejected, plugin keeps running): malformed
  `WireBuffer`, oversized payload, capability allowlist mismatch inside
  a host fn that's normally allowed.

The host MUST surface the cause via tracing. Plugin authors SHOULD
emit diagnostics through `ainb_log` rather than `println!` — `fd_write`
is stubbed and writes go to a per-plugin capture buffer that is only
drained by `dispatch_cli`.

## 7. Versioning

* A plugin's `ainb_min_version` declares the host floor. Hosts at
  `host_version < ainb_min_version` MUST refuse to load it with an
  actionable error naming both versions.
* The host's `host_version` is the contract version of the host-fn
  table above. Adding a new `ainb_*` import bumps minor; changing a
  signature bumps major and refuses plugins declaring an
  `ainb_min_version` whose major doesn't match.
* Contract `v1` is fixed: it represents the surface a plugin can safely
  rely on through the entire `1.x` host series.
* Removing a host-fn requires a contract version bump (`v2`).

## 8. Anti-validation requirements

A conforming host MUST NOT:

* Hardcode responses for plugins by name. (CTS uses UUID-shaped plugin
  ids per run.)
* Emulate plugins in-process when the wasm bytes look "trusted". (CTS
  forces wasmi instantiation through the public API.)
* Swallow panics silently. (`_init` panic MUST land in `LoadOutcome::failed`
  with an explanatory message; `_render` / `_tick` panic MUST mark the
  plugin degraded with a non-empty error chain.)
* Leak state across plugins. (Each plugin MUST get its own `Store` and
  its own data dir under `data/<plugin>/`.)

A conforming plugin SHOULD:

* Declare only the capabilities it actually uses.
* Emit per-axis sentinels through `ainb_log` so the CTS can prove the
  wasm executed (the host can't fake a sentinel without parsing and
  replaying the plugin).
* Avoid `std::env` and `std::fs` — wasmi's WASI stubs return ENOSYS for
  most of those.

## 9. Conformance test suite

The `ainb-plugin-cts` crate exposes:

```rust
pub fn run_contract_v1(wasm_bytes: &[u8]) -> ConformanceReport;
pub fn run_contract_v1_self_build() -> ConformanceReport;

pub struct ConformanceReport {
    pub plugin_name: String,
    pub plugin_version: String,
    pub ainb_min_version: String,
    pub axes: Vec<AxisOutcome>,
}

pub struct AxisOutcome {
    pub axis: u8,           // 1..=12
    pub name: &'static str,
    pub status: AxisStatus, // Pass / Fail { reason } / Skip { reason }
}
```

The report's `summary()` method renders the same shape as the host CTS
log lines, e.g.:

```
ainb-plugin-cts v0.1  contract v1
Plugin: burndown v0.1.0
[ OK ]    1  manifest schema
[ OK ]    2  init lifecycle
[ OK ]    3  render: buffer dims valid
[ OK ]    4  capability declarations match host-fn imports
[SKIP]    5  event-bus (plugin declares no subscriptions)
…
```

Plugin authors MUST run `run_contract_v1` (or `run_contract_v1_self_build()`)
in `tests/conformance.rs` before shipping a release. CI for
`ainb-plugin-burndown` exercises `run_contract_v1_self_build()` as the
in-tree dogfood gate.

## 10. Stability promise

* Adding new optional manifest keys, host-fn imports, or
  `PluginEvent` variants stays in v1.
* Renaming or removing an existing manifest key, host-fn, or variant
  bumps the contract to v2.
* Plugins that conform to v1 SHOULD load and run on every host that
  ships within the same `1.x` host_version range.

Changes are tracked in `docs/plugin-spec/CHANGELOG.md`.
